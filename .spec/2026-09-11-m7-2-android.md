# Spec: M7.2-android — Signing, deep links y QA (preparación) (#33)

**Status**: PARTIAL / BLOCKED · **Spec ID**: 2026-09-11-m7-2-android
**Issue**: #33 · **Branch**: `feat/f7` · **Depends**: M7.1

---

## Objetivo

Preparar Android release (deep links, signing config segura, build profile) en lo que **no** requiere cuentas/credenciales/dispositivo.

## Preparado aquí (code/config)

1. **Deep link de reset**: verificar que el scheme `101tags` soporta el deep link de reset de password (`101tags://reset...` / `expo-linking`). Documentar el path exacto y que `app.json.scheme` + `expo-router` lo reciben. Config Android intent filters si aplica (`expo-linking` en app.json).
2. **Signing seguro**: asegurar `.gitignore` cubre keystores (`*.keystore`, `*.jks`, `keystore.properties`, `credentials.json`) y NO commitear secretos. Documentar el flujo EAS (`eas credentials`) sin guardar el keystore en repo.
3. **eas.json**: perfiles `development`/`preview`/`production` (android buildType apk/app-bundle). Sin credenciales.
4. **Documentar** pasos de build release (`eas build -p android`) como **BLOQUEADOS** hasta tener cuenta Google/EAS del usuario.

## BLOQUEADO (requiere recursos externos)

- [ ] Build release reproducible → requiere cuenta Expo/EAS + keystore del usuario.
- [ ] Flujos críticos en dispositivo/emulador → requiere dispositivo/simulador.
- [ ] Firma real de AAB para Play → requiere Play Console.

> Estos criterios **no** se marcan DONE hasta que el usuario aporte cuentas/EAS/dispositivo.

## Verificación

- `app.json`/`eas.json` JSON válidos; `pnpm typecheck`/`lint` exit 0.
- Test que afirma `.gitignore` incluye patrones de keystore y que no existe ningún `*.keystore|*.jks` trackeado (`git ls-files`).

## Definition of Done

- [ ] `.gitignore` + `eas.json` + deep link documentado.
- [ ] Criterios bloqueados documentados explícitamente (no marcados DONE).
