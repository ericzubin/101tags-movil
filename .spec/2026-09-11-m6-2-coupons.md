# Spec: M6.2-coupons — Cupones wallet/validación (#30)

**Status**: APPROVED · **Spec ID**: 2026-09-11-m6-2-coupons
**Issue**: #30 · **Branch**: `feat/f6` · **Depends**: F3

---

## Objetivo

Cuponera del usuario (lista con validez) y validación real en contexto de checkout.

## Contratos

- `GET /coupons?email=&q=` → `{ data: CouponDefinition[] }` (ya filtrado: activos, no expirados, asignados al email o públicos).
  `CouponDefinition`: `id` (`api-<id>`), `code`, `issuer`, `title`, `description`, `discountType`, `value`, `minSubtotal`, `segment`, `storeName`, `assignedEmails`, `expiresAt`, `oneTime`, `keywords`.
- `POST /coupons/validate` → `{ valid, message, coupon?, discount_amount, shipping_discount, eligible_subtotal }` — **ya implementado** en `checkout-service.validateCoupon` (M3.2); reutilizar.

## Arquitectura

- `src/core/models/coupon.model.ts`: `CouponDefinition`, `CouponValidation` (re-export/alineado con checkout si ya existe).
- `src/core/services/coupon-service.ts`: `getCoupons({ email?, q? })`.
- `src/stores/coupon-store.ts` (o hooks): `coupons`, `status`, `error`, `fetchCoupons(email?)`, `filter(q)`; `validation` reutiliza checkout-store.
- UI: `src/app/coupons.tsx` (cuponera): lista con código, título, descripción, descuento legible y `expiresAt`; búsqueda (`q`); cupón no aplicable/no elegible se muestra igual con su razón cuando exista. Entrada desde `(tabs)/account.tsx` y opción de aplicar en checkout (usa `checkout-store.applyCoupon` con items del carrito).
- Descuento legible: `discountType` porcentaje/fijo/envío gratis (`value`).

## Seguridad

- Auth; usar `email` del usuario autenticado (no pedir emails ajenos). No loggear datos personales.

## Escenarios BDD

- **AC1**: `fetchCoupons()` llama `GET /coupons?email=` y mapea `data`.
- **AC2**: lista muestra code/title/discount y `expiresAt` legible.
- **AC3**: búsqueda usa `q` y filtra la lista.
- **AC4**: aplicar cupón en checkout llama `validateCoupon` real (reutiliza checkout) con items del carrito.
- **AC5**: cupón inválido/expirado → muestra `message` del backend (razón utilizable), sin romper.
- **AC6**: lista vacía → EmptyState; error → ErrorState retry.

## Definition of Done

- [ ] model + service + store + UI + tests (AC1–AC6).
