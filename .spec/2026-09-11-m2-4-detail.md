## Contexto

El backend expone `GET /api/catalog/products/{slug}` con `variants[]` (size, color, sku, stock, price, priceOverride, inStock). No hay endpoint de stock en tiempo real; el stock del response es la mejor fuente (revalidar en F3 al agregar al carrito).

M2.0 ya entregó: `catalogService.getProductBySlug()`, `catalogKeys.product(slug)`, `<Image>`, `<Skeleton>`, `<EmptyState>`, `<ErrorState>`, `<Button>`, `formatMXN`.

## Objetivo

1. Ruta root-level `src/app/product/[slug].tsx` (fullscreen sobre tabs) registrada en `src/app/_layout.tsx`.
2. Galería con paginación horizontal + indicador `N/M`.
3. Selector de variantes (talla/color) con disponibilidad calculada: deshabilitar combinaciones sin stock.
4. QuantityStepper limitado por stock de la variante seleccionada.
5. AddToCartButton: deshabilitado hasta que haya variante con stock; al presionar → placeholder (Alert "El carrito llega en F3") — NO lógica de carrito.
6. Estados: loading (skeleton), error (ErrorState + retry), 404 (EmptyState "Producto no encontrado").

## Fuera de alcance

- Carrito real (F3).
- Reviews de producto (backend no tiene endpoint).
- Productos relacionados (backend no tiene endpoint).
- Deep links/share (F7), aunque la ruta `101tags://product/<slug>` funcionará gratis.

## Contratos

### `variant-logic.ts` (puro, testeable)

```ts
import type { ProductVariantSummary } from '@/core/models/catalog';

export function availableColors(variants: ProductVariantSummary[], size?: string | null): string[] {
  const pool = variants.filter((v) => !size || v.size === size);
  return unique(pool.filter((v) => v.stock > 0).map((v) => v.color).filter((c): c is string => !!c));
}

export function availableSizes(variants: ProductVariantSummary[], color?: string | null): string[] {
  const pool = variants.filter((v) => !color || v.color === color);
  return unique(pool.filter((v) => v.stock > 0).map((v) => v.size).filter((s): s is string => !!s));
}

export function findVariant(
  variants: ProductVariantSummary[],
  size: string | null,
  color: string | null,
): ProductVariantSummary | null {
  return variants.find((v) => v.size === size && v.color === color) ?? null;
}

export function isSelectable(
  variants: ProductVariantSummary[],
  size: string | null,
  color: string | null,
): boolean {
  return findVariant(variants, size, color)?.stock ? true : false;
}

export function clampQuantity(qty: number, max: number): number {
  if (max <= 0) return 0;
  return Math.min(Math.max(1, Math.floor(qty)), max);
}

function unique<T>(arr: T[]): T[] {
  return Array.from(new Set(arr));
}
```

⚠️ Reglas de producto sin variantes: si `variants.length === 0`, el producto no se puede agregar (AddToCart deshabilitado, texto "No disponible").

## Riesgos / caveats

1. **`src/app/_layout.tsx` es compartido**: M2.1 NO lo toca; M2.4 sí (1 línea). Sin conflicto en paralelo.
2. **`Alert.alert` en tests**: mockear `react-native`'s Alert o spyOn. Patrón: `jest.spyOn(Alert, 'alert')`.
3. **`useLocalSearchParams` ya está mockeado en jest.setup.js** (M1.10); verificar que el mock permite setear slug por test (`jest.mock` override local si hace falta).
4. **Producto sin variantes** (raro pero posible): AddToCart deshabilitado, mostrar "No disponible".
5. **Preselección**: solo cuando hay exactamente 1 opción disponible en ese eje; si hay ≥2, requiere selección explícita.
6. **Reset de qty** al cambiar variante: setQty(clampQuantity(qty, newVariant.stock)) — nunca dejar qty > stock.
