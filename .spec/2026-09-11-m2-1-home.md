## Contexto

`src/app/(tabs)/index.tsx` es un placeholder ("101tags / Bienvenido"). El backend ya expone:
- `GET /api/home-content` → `{ data: { hero, featured_category, featured_media, ribbon } }`
- `GET /api/catalog/products?featured=1&per_page=8` → paginado

M2.0-setup ya entregó: `homeService.getHomeContent()`, `catalogService.getProducts()`, `homeKeys`, `catalogKeys`, `<Image>`, `<Skeleton>`, `<EmptyState>`, `<ErrorState>`, `formatMXN`, `resolveMediaUrl`.

## Objetivo

1. Reescribir `src/app/(tabs)/index.tsx` como Home real: hero carousel + grid de categorías + fila de productos destacados (+ ribbon si existe).
2. Crear componentes en `src/components/home/` y `src/components/catalog/ProductCard.tsx` (compartido con M2.3).
3. Usar TanStack Query (`useQuery`) por primera vez en el proyecto — respetar defaults del QueryClient.
4. Estados loading (skeleton) / error (ErrorState + retry) / empty.
5. Navegación: tap en categoría → `/(tabs)/catalog?category=<slug>`; tap en producto → `/product/<slug>`.

## Fuera de alcance

- Pantalla de catálogo/lista (M2.2/M2.3).
- Pantalla de detalle (M2.4, en paralelo).
- Sponsored ads en home (F2.5 si aplica; no incluir).
- Deep links.

## Componentes

### `src/components/catalog/ProductCard.tsx` (compartido)

```tsx
import { Pressable, Text, View } from 'react-native';
import { Image } from '@/components/ui/Image';
import { formatMXN } from '@/core/utils/format-currency';
import type { ProductSummary } from '@/core/models/catalog';

export interface ProductCardProps {
  product: ProductSummary;
  onPress?: (product: ProductSummary) => void;
  testID?: string;
}

export function ProductCard({ product, onPress, testID }: ProductCardProps) {
  return (
    <Pressable
      onPress={() => onPress?.(product)}
      testID={testID ?? `product-card-${product.slug}`}
      accessibilityRole="button"
      accessibilityLabel={`${product.name}, ${formatMXN(product.minPrice)}`}
      className="w-40 mr-3 bg-white rounded-lg overflow-hidden active:opacity-80"
    >
      <Image source={product.image} width={160} height={160} contentFit="cover" testID="product-card-image" />
      <View className="p-2">
        <Text numberOfLines={2} className="font-brand text-sm text-brand-dark">{product.name}</Text>
        <Text className="font-brand-bold text-base text-brand-primary mt-1">{formatMXN(product.minPrice)}</Text>
        {!product.inStock && (
          <Text className="font-brand text-xs text-red-600 mt-1">Sin stock</Text>
        )}
      </View>
    </Pressable>
  );
}
```

**Helper de normalización** (en el mismo archivo o `src/components/home/normalize-home-content.ts`):

```ts
export function normalizeHomeContent(data: HomeContentResponse['data'] | undefined): HomeContentByPlacement | null {
  if (!data) return null;
  if (Array.isArray(data)) return null;  // no esperado sin placement
```

## Riesgos / caveats

1. `HomeContentResponse['data']` es union (`ByPlacement | Item[]`). Normalizar defensivamente (scope: sin placement → objeto; si viene array, ignorar).
2. Tests mockean `useQuery` (jest.mock('@tanstack/react-query')) o `QueryClientProvider` con QueryClient de test — seguir el patrón que ya exista en `_layout.spec.tsx`/`font-loading.spec.tsx` (mocks children-passthrough).
3. `Dimensions.get('window').width` en tests jest-expo retorna 750 por default; no assert exacto de ancho.
4. `featured` query usa `perPage: 8`; el backend acepta `per_page` (máx 48). `serializeFilters` ya mapea.
5. No tocar `(tabs)/_layout.tsx` ni `catalog.tsx` (M2.2/M2.3 lo harán).
