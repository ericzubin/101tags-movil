## Contexto

`M2.2` entregó `(tabs)/catalog.tsx` con modo `tree` (CategoryTree) y modo `list` básico: un `useQuery` de `getProducts({ category|subcategory })`, primera página, dentro de `ScrollView` + `ProductGrid`. El backend ya expone todo lo necesario para filtrar/ordenar/paginar, y `catalogService.getProducts` ya serializa `CatalogFilters`.

### Hallazgo de contrato (bloqueante) — paginación flat

`GET /api/catalog/products` (`CatalogController::products`) responde `response()->json($products)` sobre un `LengthAwarePaginator`, es decir un paginador **flat**:

```json
{
  "current_page": 1,
  "data": [ ... ],
  "last_page": 5,
  "per_page": 12,
  "total": 60,
  "from": 1,
  "to": 12,
  "next_page_url": "https://.../api/catalog/products?page=2",
  "prev_page_url": null,
  ...
}
```

El cliente móvil aplica `toCamel` recursivo (`src/core/api/client.ts`), por lo que en runtime las claves quedan `data`, `currentPage`, `lastPage`, `perPage`, `total`.

Sin embargo, `src/core/models/common.model.ts` modela `Paginated<T>` como `{ data, meta: { current_page… }, links: {…} }` (**anidado y snake_case**). El storefront confirma el shape flat (`storefront/src/types/catalog.ts:95`, `ProductListView.vue:295` usa `res.last_page`). M2.2 solo lee `.data` y por eso no ha fallado, pero `useInfiniteQuery` necesita `lastPage`/`currentPage`: con el modelo anidado `data.meta.lastPage` sería `undefined` → la paginación no avanzaría.

**Decisión (aprobada por el usuario):** corregir `Paginated<T>` al shape flat camelCase real. `Paginated<T>` solo lo consume `CatalogProductListResponse` (`catalog.model.ts:108`), así que el cambio es seguro y localizado.

## Problema

1. El modo lista solo muestra la primera página y no permite cargar más.
2. No hay búsqueda, orden ni filtros móviles (talla/color/precio/stock/oferta).
3. `Paginated<T>` no refleja el contrato real, impidiendo paginar.

## Objetivo

Convertir el modo lista de `(tabs)/catalog.tsx` en una lista infinita (`useInfiniteQuery`) con búsqueda debounced, chips de orden y un `FilterSheet` (RN `Modal`), consumiendo `GET /api/catalog/products` y `GET /api/catalog/filters`, sin duplicar productos ni pisar estado con requests obsoletos.

## Fuera de alcance

- Cambios al backend.
- Selector de segmento (se mantiene `DEFAULT_SEGMENT='basicos'`).
- Slider de precio con dependencia nueva → se usan inputs numéricos + presets.
- Pull-to-refresh (opcional, no requerido).
- Rediseño del árbol (M2.2 intacto).
- Reemplazo/borrado de `ProductGrid` (se conserva; ver §Compatibilidad).

## Arquitectura afectada

- **Page**: `src/app/(tabs)/catalog.tsx` (modo `list`).
- **Components**: nuevos `SortChips`, `FiltersSheet`.
- **Models**: `src/core/models/common.model.ts` (`Paginated<T>` flat).
- **Services**: `src/core/services/catalog-service.ts` (`getProducts` acepta `signal`).
- **Keys**: `catalogKeys.products(filters)` ya existente (sin cambios).

## Contratos

### API consumida (read-only)

| Método | Path | Auth | Query | Response | Errores |
|---|---|---|---|---|---|
| GET | `/api/catalog/products` | pública | `q, category, subcategory, sizes, colors, price_min, price_max, segment, featured, in_stock, on_sale, sort, page, per_page` | `Paginated<ProductSummary>` flat | 422, 5xx |
| GET | `/api/catalog/filters` | pública | `segment, category` | `FilterOptions` (camelCase tras `toCamel`) | 5xx |

- `category`/`subcategory`/`sizes`/`colors` se serializan CSV (`serializeFilters` ya lo hace).
- `sort ∈ { newest, price_asc, price_desc }`; backend default `newest`.
- `per_page` backend default `12`, máx `48`. No se envía `perPage` (usar default).

### `FilterOptions` (ya en `catalog.model.ts`)

```ts
interface FilterOptions {
  sizes: string[];
  colors: string[];
  priceMin: number;
  priceMax: number;
  categories: FilterOptionCount[];
  subcategories: FilterOptionCategory[];
}
```

### `Paginated<T>` corregido (`common.model.ts`)

```ts
export interface Paginated<T> {
  data: T[];
  currentPage: number;
  lastPage: number;
  perPage: number;
  total: number;
  from: number | null;
  to: number | null;
  nextPageUrl: string | null;
  prevPageUrl: string | null;
}
```

- Se **eliminan** `PaginatedMeta` y `PaginatedLinks` (sin otros consumidores; verificado por grep).
- `CatalogProductListResponse = Paginated<ProductSummary>` no cambia.

### `catalogService.getProducts` (firma extendida, retrocompatible)

```ts
async getProducts(
  filters: CatalogFilters = {},
  options: { signal?: AbortSignal } = {},
): Promise<CatalogProductListResponse> {
  return httpClient.request<CatalogProductListResponse>('/catalog/products', {
    method: 'GET',
    query: serializeFilters(filters),
    signal: options.signal,
  });
}
```

## Componentes

### `src/components/catalog/SortChips.tsx`

```tsx
export type SortKey = 'newest' | 'price_asc' | 'price_desc';

export interface SortChipsProps {
  value: SortKey;
  onChange: (sort: SortKey) => void;
  testID?: string;
}
```

- 3 chips: `newest` → "Recientes", `price_asc` → "Precio ↑", `price_desc` → "Precio ↓".
- testID por chip: `sort-newest`, `sort-price_asc`, `sort-price_desc`.
- Chip activo: estilo `bg-brand-primary text-white`; inactivo `bg-white`; `accessibilityRole="button"` + `accessibilityState={{ selected }}`.
- Contenedor testID default `sort-chips`.

### `src/components/catalog/FiltersSheet.tsx`

```tsx
export interface FiltersValue {
  sizes: string[];
  colors: string[];
  priceMin?: number;
  priceMax?: number;
  inStock?: boolean;
  onSale?: boolean;
}

export interface FiltersSheetProps {
  visible: boolean;
  options: FilterOptions | null;
  value: FiltersValue;
  loading?: boolean;
  onApply: (value: FiltersValue) => void;
  onClear: () => void;
  onClose: () => void;
  testID?: string;
}
```

- `Modal` built-in de RN (`transparent`, `animationType="slide"`, `onRequestClose={onClose}`).
- Draft local inicializado desde `value` cada vez que `visible` pasa a `true`.
- Secciones:
  - **Tallas** (`options.sizes`): chips multi-toggle, testID `filter-size-<size>`.
  - **Colores** (`options.colors`): chips multi-toggle, testID `filter-color-<color>`.
  - **Precio**: `TextInput` numéricos `filter-price-min` / `filter-price-max` (bounded por `options.priceMin/priceMax`) + presets calculados con `mid = Math.round((priceMin+priceMax)/2)`:
    - `filter-price-preset-low` → "Hasta {mid}" (`priceMax=mid`).
    - `filter-price-preset-mid` → "{min}–{max}" (ambos).
    - `filter-price-preset-high` → "Más de {mid}" (`priceMin=mid`).
    - Presets solo si `priceMax > priceMin > 0`; si no, solo inputs.
  - **Toggles**: RN `Switch` `filter-in-stock` ("Solo con stock"), `filter-on-sale` ("En oferta").
- Footer: `filters-sheet-clear` ("Limpiar") → `onClear()` + draft vacío; `filters-sheet-apply` ("Aplicar") → `onApply(draft)`.
- Cierre sin aplicar: X header `filters-sheet-close` y presión de backdrop → `onClose()`.
- `loading` → muestra un indicador de carga de opciones; los chips se renderizan con `options` cuando llegue.
- `visible=false` → no debe haber contenido interactuable ni disparar handlers.

### `src/app/(tabs)/catalog.tsx` (solo modo `list`; modo `tree` intacto)

Estado adicional en el componente:

```ts
const [search, setSearch] = useState('');
const [debouncedSearch, setDebouncedSearch] = useState('');
const [sort, setSort] = useState<SortKey>('newest');
const [filters, setFilters] = useState<FiltersValue>(EMPTY_FILTERS);
const [sheetOpen, setSheetOpen] = useState(false);
```

- **Debounce** de búsqueda 350 ms vía `useEffect` + `setTimeout`/`clearTimeout`.
- `combinedFilters: CatalogFilters` = `{ category|subcategory, q: debouncedSearch || undefined, sort, sizes?, colors?, priceMin?, priceMax?, inStock?, onSale? }`. `category`/`subcategory` provienen de `selection` (M2.2).
- **Query de productos**:

```ts
const productsQuery = useInfiniteQuery({
  queryKey: catalogKeys.products(combinedFilters),
  queryFn: ({ pageParam, signal }) =>
    catalogService.getProducts({ ...combinedFilters, page: pageParam }, { signal }),
  initialPageParam: 1,
  getNextPageParam: (lastPage) =>
    lastPage.currentPage < lastPage.lastPage ? lastPage.currentPage + 1 : undefined,
  enabled: !!selection,
});
```

- **Query de opciones de filtro** (solo al abrir el sheet):

```ts
const filtersQuery = useQuery({
  queryKey: catalogKeys.filters(DEFAULT_SEGMENT, categorySlug),
  queryFn: () => catalogService.getFilters(DEFAULT_SEGMENT, categorySlug),
  enabled: sheetOpen,
});
```

donde `categorySlug` = `selection?.kind === 'category' ? selection.slug : undefined`.

- **Header del modo lista** (se conserva el back-to-tree de M2.2):
  - Botón `catalog-back-to-tree` (ya existe) + título.
  - `TextInput` `catalog-search-input`, placeholder "Buscar productos", `returnKeyType="search"`, `autoCorrect={false}`.
  - `SortChips`.
  - Botón `catalog-open-filters`: texto "Filtros" + badge con conteo de filtros activos del sheet (suma de longitudes/campos activos).
- **Lista**: `FlatList` (`testID="catalog-product-list"`, `numColumns={2}`, `columnWrapperStyle={{ justifyContent: 'space-between' }}`) con:
  - `data` = `dedupeBySlug(productsQuery.data?.pages.flatMap((p) => p.data) ?? [])`.
  - `keyExtractor={(p) => String(p.id)}`.
  - `renderItem` → `<View className="w-1/2 p-1"><ProductCard product={item} onPress={onSelectProduct} className="mr-0 w-full" /></View>`.
  - `onEndReached={() => { if (productsQuery.hasNextPage && !productsQuery.isFetchingNextPage) void productsQuery.fetchNextPage(); }}` + `onEndReachedThreshold={0.5}`.
  - `ListFooterComponent`: `ActivityIndicator` `catalog-list-loading-more` cuando `isFetchingNextPage`.
  - `ListEmptyComponent`: `EmptyState` "Sin productos" cuando no loading y 0 items.
  - `testID` de item: `catalog-list-item-<slug>` en el wrapper (para dedupe test).
- **Estados**:
  - Primera carga (`isLoading`) → `catalog-list-skeleton` (existente).
  - Error de primera página (`isError && !data`) → `ErrorState` `catalog-list-error` + retry.
  - Tap producto → `router.push('/product/<slug>')`.
- **Anti-obsoletos**: la `queryKey` incluye `combinedFilters`, de modo que cada combinación vive en su propia entrada de caché; resultados de una key vieja no sobrescriben la nueva. `signal` cancela el fetch al desmontar/cambiar. No se muta estado local con la respuesta.

## Seguridad

- Endpoints públicos; no se envían credenciales más allá del bearer global existente.
- No se persisten filtros/búsqueda en storage.
- `priceMin/priceMax` se sanean a número ≥ 0; si el input no es numérico se ignora.

## Compatibilidad

- **Modo `tree` (M2.2) sin cambios**: CategoryTree, chevrons, loading/error/empty.
- **`ProductGrid`** y su spec se conservan verdes (la lista ahora usa `FlatList` por virtualización; `ProductGrid` queda disponible para grids no paginados). No se borra.
- **`ProductCard`** no cambia (ya acepta `className` desde M2.2).
- **`catalogKeys.products`** sin cambios: el objeto `combinedFilters` es la key.
- La home (`(tabs)/index.tsx`) usa `useQuery` con `catalogKeys.products({ featured, perPage: 8 })`; no se toca.
- `catalog-service.spec.ts` existente debe seguir verde (los mocks no dependen de `Paginated`).

## Riesgos

1. **Cambio de tipo `Paginated<T>`**: rompe `common.model.spec.ts` (se reescribe). Sin otros consumidores.
2. **`useInfiniteQuery` no mockeado** en `jest.setup.js`; los tests de `catalog.spec.tsx` deben mockearlo localmente (igual que hacen con `useQuery`).
3. **FlatList en tests**: `onEndReached` no se dispara por scroll en jsdom; los tests lo invocan explícitamente vía `fireEvent(list, 'endReached')` o llamando la prop.
4. **Debounce con timers**: usar `jest.useFakeTimers()` + `jest.advanceTimersByTime(350)`.
5. **`Switch` en tests**: usar `fireEvent(switch, 'valueChange', true)`.
6. **Dedupe**: si `per_page` cambia o el backend reordena entre páginas puede repetir items; el dedupe por `id` lo mitiga.
7. **Doble `catalogKeys.products`** entre home (`useQuery`) e infinite (`useInfiniteQuery`): son keys distintas por filtros, sin colisión.
